# Следующий этап AI

Пользователь задаёт вопрос → backend находит релевантные данные NASA → AI
анализирует предоставленные результаты → frontend показывает ответ с источниками.

1. Пользователь выбирает исследование и задаёт вопрос.
2. Backend выбирает проверенные строки CSV и/или фрагменты документов.
3. AI получает вопрос, материалы и их источники. При недостатке данных сообщает
   об этом, не выдумывает измерения или выводы.
4. Backend возвращает ответ, ссылки и использованные ID записей.

Сейчас есть каталог, загрузчик и интерфейс `ExperimentAnalyzer` в `app/ai.py`.
Модель не подключена, `ai_available: false`. AI endpoints не создавались.

До реализации согласовать:

- Один сценарий: объяснение имеющихся результатов, поиск или прогноз?
  Для прогноза отдельно нужны целевая величина, обучающие данные и проверка качества.
  Описания каталога не заменяют экспериментальные измерения.
- Принадлежность CSV исследованиям, происхождение, версии, словарь полей,
  единицы, пропуски и условия использования данных.
- Отбор материалов для вопроса. Сначала достаточно явного выбора исследования
  и фильтров; сложный RAG пока не нужен.
- Модель, место запуска, допустимые расходы и передача данных внешнему сервису.
- JSON для frontend: ответ, источники, использованные записи, ограничения,
  ошибки и время ожидания.
- Контрольные вопросы и проверенные ответы от аналитиков. Числовые расчёты
  проверять отдельно; ссылки на источники обязательны.
- Исключение mock из научных ответов, разделение фактов и гипотез.
  Инструкции внутри исходных документов не должны управлять приложением.

После согласования реализовать один анализатор за существующим интерфейсом
и один согласованный маршрут. Сейчас ключи, модели, AI-библиотеки и сетевые
вызовы не добавлены.
